# Writing style for this project

All documents follow rules that are inspired by ASD-STE100 (Simplified Technical English). This is not a formal STE check. The goal is text that anyone can read without effort.

## Rules

1. Use short sentences. Procedures: 20 words or fewer. Descriptions: 25 words or fewer.
2. Give one instruction or one idea in each sentence.
3. Use the active voice. Write "The runner saves the trajectory", not "The trajectory is saved".
4. Use the simple present tense for facts. Use the imperative for steps ("Run the tests.").
5. Use one word for one concept. Use the words in `docs/glossary.md`. Do not use synonyms.
6. Do not use idioms, jokes or figurative language.
7. Keep the article ("the", "a") and do not drop words to save space.
8. Use a numbered list for steps that must happen in order. Use a table for facts that compare.
9. Show numbers with their unit. Write "4 trials per task", not "4 per".
10. Write what a thing is before you write how it works.
11. State limits and known problems plainly. Do not hide them.
